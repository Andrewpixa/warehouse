# 架构设计

**课程：** 药企进销存（B/S）  
**配套：** [技术选型](./技术选型.md)、网页图册 `/design`、`docs/pharma-er-uml.md`

## 1. 系统放在哪一层

浏览器和手机只谈作业。Nginx 分两路：静态页给 Vue，`/warehouse` 给 Spring Boot。库存、单据、追溯都进 MySQL 库 `pharma_ims`。登录、菜单、角色用 `sys_*`，与药企业务表同库、模型分开。

```text
Web / 小程序 / App / 桌面
        │
     Nginx
     ├── /              warehouse-front/dist
     └── /warehouse     Spring Boot :8899
                            │
                      Controller
                            │
                      Service + 事务
                      SA-Token / 操作日志 AOP
                            │
                      MyBatis-Plus
                            │
                      MySQL（档案 / 单据 / 批号库存 / 追溯 / 日清月结）
```

## 2. 后端怎么分层

每个业务模块走同一条线：`Controller → Service → Mapper → XML/表`。

| 层 | 职责 | 不做什么 |
|---|---|---|
| Controller | 收参数、回 `ResultObj` / `DataGridView` | 不写库存加减 |
| Service | 草稿、确认、红冲、收货；开事务 | 不直接拼前端 HTML |
| Mapper | SQL 与条件 UPDATE | 不处理会话 |
| 前端 | 表格、扫码、打印、图表 | 不信任按钮权限，接口仍要校验 |

系统模块在 `sys/`（用户、角色、部门、菜单、日志）。  
业务模块在 `bus/`（档案、进货、出库、库存、追溯、结账、报表）。

## 3. 库怎么切

药企账粒度不是「一个商品一个数」，而是：

```text
uk_batch_stocks (drug_id, warehouse_id, batch_no, quality_status)
```

一物一批一库一质量状态 = 一条库存。进货确认加、出库确认减、红冲确认加回、升益按实盘减账面。

| 层 | 主要表 | 说明 |
|---|---|---|
| 档案 | `drugs` `customers` `suppliers` `warehouses` | 品种、医院客户、供应商、仓 |
| 进货 | `purchase_orders` + `items` | 草稿不改库存 |
| 出库 | `sales_orders` + `items` | 同一张表表达正常 / 红冲 / 回款 / 收货 |
| 库存 | `batch_stocks` `surplus_orders` | 升益按差额调账 |
| 追溯 | `trace_codes` `trace_pack_relations` | 码靠 `spdid` 对齐明细 |
| 结账 | `daily_close_records` `monthly_close_records` | 按日/月快照，不挂单据外键 |

旧仓管 `bus_*` 按 SKU 扣库存，与药企账不要画在一张 ER 上。

## 4. 模块与主链路

课堂验收主链路：

```text
品种 / 供应商 / 客户
  → 采购入库（批号、效期，确认后入账）
  → 批号库存
  → 追溯码（发票号 / SPDID / 扫码）
  → 销售出库（库存不足拒绝）
  → 医院收货（重复提交拒绝）
  → 日清 / 月结
```

附加：盘点、调拨、分仓库存、进销报表。移动端做盘点和查询，不替代 Web 开单。

## 5. 部署与运维

| 项 | 做法 |
|---|---|
| 构建 | 后端 `mvn -DskipTests=false test` 打 JAR；前端 `npm run build` 出 `dist` |
| 运行 | Java 听 8899；Nginx 80/443；MySQL 本机或同机 |
| 发布 | 先备份，再换 JAR，再覆盖静态页，最后巡检 |
| 回滚 | 前端换上一版 `dist`；后端换上一版 JAR；结构失败用 `deploy/restore.sh` |
| CI | `.github/workflows/ci.yml`：push / PR 跑后端测试 + 前端打包 |

演示环境可以先 HTTP。生产必须是备案域名 + HTTPS + 岗位账号，见 `docs/delivery/`。
