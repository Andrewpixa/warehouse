# 技术选型

**课程：** 药企进销存（B/S）  
**篇幅：** 短文，答辩用  
**配套：** [架构设计](./架构设计.md)、网页图册 `/design`、`docs/pharma-er-uml.md`

## 1. 结论

继续用开源仓管底座的技术栈。领域模型按药品流通改（批号库存、追溯、日清月结），不另换语言或数据库。

| 层 | 选定 | 不选 | 原因 |
|---|---|---|---|
| 后端 | Java 21 + Spring Boot 3.5 | .NET / Node | 底座已是 Spring；事务、REST、作业确认好写 |
| 持久化 | MyBatis-Plus + MySQL 8 | JPA、SQL Server | XML/注解混用够用；本机和演示机都好装 |
| 权限 | SA-Token | 自研 Session | 会话 Cookie，菜单和按钮权限能对上岗位 |
| Web | Vue 3 + TypeScript + Element Plus | 服务端渲染页 | 前后端分离，表格、打印、图表够用 |
| 移动 | uni-app X、Flutter | 只做 H5 | 盘点、查询、扫码分端，不和 Web 抢同一套页 |
| 图与文档 | Mermaid | 只交 Word 截图 | 仓库里改一处，网页 `/design` 能画出来 |

## 2. 为什么不换 SQL Server

附录口径与 `docs/pharma-er-uml.md` 一致：业务模型按药企进销存设计；开发与演示统一 MySQL。只有老师点名、实习单位现网是 SQL Server，或必须走 SQL Server ODBC 时才迁。迁的是表结构与驱动，不推翻「药品 × 仓库 × 批号 × 质量状态」这条账。

## 3. 关键能力怎么落地

| 能力 | 怎么实现 | 选型关系 |
|---|---|---|
| 草稿不入账 | 单据 `status=草稿/已确认`，确认才改库存 | 靠 Spring 事务，一次确认整单过账 |
| 防超卖 / 防超退 | 批号库存条件 UPDATE | MySQL 行锁 + 原子 SQL，不靠先查再改 |
| 岗位权限 | 角色菜单 + 接口 `view/create/update/delete` | SA-Token 拦截，前端按钮只是展示 |
| 追溯扫码 | 码挂 SPDID；大码解析包装树 | 库表自关联；手机端摄像头，Web 用扫码枪 |
| 报表 | 已确认单据聚合，日清月结另存快照 | 不另建数仓，课程规模用 SQL 汇总即可 |

## 4. 风险与取舍

- 多端（Web / 小程序 / Flutter / Electron）增加维护面；本期课堂验收以 Web 主链路为准。
- 无独立测试库时，`mvn test` 不启动完整 Spring 上下文，避免 CI 连不上 MySQL。
- 公网演示若仍是 HTTP，不能当成生产形态；生产要域名和 HTTPS，见 `docs/delivery/01-生产形态-域名与HTTPS.md`。
