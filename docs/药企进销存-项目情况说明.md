## 一、项目定位

本系统是一套面向 **药品流通企业** 的进销存管理系统（Pharma IMS）。

核心目标不是只记「有没有货」，而是把日常作业做成可核对、可追溯的闭环：

- 采购入库 → 批号库存 → 销售出库 → 医院收货
- 批号、效期、追溯码随货流转
- 日清检查、月结对账，便于对账与检查

系统名称：**药企进销存**。

## 四、本期验收口径（已书面冻结）

详见 [`docs/delivery/00-范围冻结与验收口径.md`](./delivery/00-范围冻结与验收口径.md) 与 ADR-0001。

**验收以药企药品流通主链路为准：**  
品种 → 采购入库（批号/效期）→ 批号库存 → 追溯码（系统内）→ 销售出库 → 医院收货 → 日清/月结。

**不列入本期：** 通用门店进销存（POS、零售、会员、提成等）、移动端、桌面端、码上放心对接、按贵司编制落地的 GSP 岗位。

## 五、已实现的主要能力（功能，非生产形态）

### 1. 药品流通主链路（本期验收范围）

| 模块 | 作用 |
|------|------|
| 品种管理 | 维护药品品种档案 |
| 供应商 / 客户 | 上游供应商、下游医院或客户档案 |
| 采购入库单 | 供应商到货入库，批号入账 |
| 批号库存 | 按批号查看数量、效期，支持近效期关注 |
| 批号升益 | 批号相关库存调整 |
| 销售出库单 | 开单出库，货与码随单据走 |
| 医院收货确认 | 下游确认收货，流向落袋 |
| 追溯码查询 | 系统内按码查询来源与流向；包装解析为本地预置树 |
| 日清检查 | 当日作业收口核对 |
| 月结对账 | 按月对账 |
| 进货统计 / 出货统计 | 进、出货汇总查看 |

2026-09-14 已对批号/效期、追溯码、防超卖、防重复收货做了实测，记录在 [`docs/delivery/02-关键路径实测记录.md`](./delivery/02-关键路径实测记录.md)。

### 2. 仓储与库存

仓库、调拨、分仓库存、盘点等仍可用，作为仓储能力补充。

### 3. 进销存通用能力（不列入本期验收）

进货 POS、销售 POS、散客零售、会员与提成等仍保留，仅对照演示。

### 4. 系统管理

人员、角色、部门、菜单、按钮级权限、公告与日志。登录有验证码；密码提交经 RSA 封装。**这不能替代 HTTPS。**

## 六、系统结构（简要）

```
浏览器  →  产品介绍 / 登录 / 业务页面（Vue 3）
                ↓
            Nginx（当前仅 80）
                ↓
     静态页面          接口 /warehouse → 后端（Spring Boot）
                                              ↓
                                         MySQL 业务库
```

生产形态要求：备案域名 + 443 + 岗位账号，见 [`docs/delivery/01-生产形态-域名与HTTPS.md`](./delivery/01-生产形态-域名与HTTPS.md)。
