# 05 运维交付包

生产未开通前，本包作为**上线前必做清单**。脚本在 `deploy/`，默认库名 `pharma_ims`、后端 `127.0.0.1:8899`、Nginx 静态站点。口令只从环境变量读取，不写进仓库。

## 1. 备份

脚本：`deploy/backup.sh`

```bash
export MYSQL_HOST MYSQL_PORT MYSQL_DB MYSQL_USERNAME MYSQL_PASSWORD
# 可选：BACKUP_DIR=/var/backups/pharma-ims
sudo -E bash deploy/backup.sh
```

产物：`$BACKUP_DIR/pharma-ims-YYYYMMDD-HHMMSS.sql.gz`，并保留最近 14 份。

建议：每天 02:00 crontab；备份文件不放在 Web 根目录。

## 2. 恢复

脚本：`deploy/restore.sh`

```bash
export MYSQL_HOST MYSQL_PORT MYSQL_DB MYSQL_USERNAME MYSQL_PASSWORD
sudo -E bash deploy/restore.sh /var/backups/pharma-ims/pharma-ims-20260914-020000.sql.gz
```

恢复会覆盖目标库，须先停应用或进入维护页，恢复后做 3. 巡检。

## 3. 监控巡检

脚本：`deploy/healthcheck.sh`（进程 + HTTP + 磁盘）。人工日检：

| 项 | 通过标准 |
|----|----------|
| `curl -fsS https://<域名>/` | 200 |
| `curl -fsS https://<域名>/warehouse/login/publicKey` | JSON `code=200` |
| `systemctl is-active pharma-ims`（或等价服务名） | active |
| `nginx -t` 且 443 监听 | 通过 |
| 磁盘使用率 | < 85% |
| 最近一份备份 | 不超过 26 小时 |
| 证书剩余天数 | > 14 |

异常：先看应用日志与 `nginx error.log`，再决定是否回滚。

## 4. 回滚

1. **仅静态前端：** 用上一版 `dist/` 覆盖 Nginx 根目录，`nginx -s reload`。  
2. **后端 JAR：** 停服务 → 换回上一版 jar → 启动 → 跑 healthcheck。  
3. **库结构变更失败：** 用变更前的 `backup.sh` 产物 `restore.sh`（会丢变更后的业务数据，须业务确认）。  
4. **HTTPS 失败：** 临时恢复 80 配置仅用于排障，**排障结束必须回到 HTTPS**；不得把 IP+HTTP 当生产。

记录：时间、操作人、版本号/备份文件名、结果。

## 5. 发布顺序（建议）

1. 备份  
2. 发后端（健康检查通过）  
3. 发前端  
4. 冒烟：登录 → 批号库存 → 一张草稿出入库（演示库）  
5. 失败则按 4 回滚  

## 6. 账号初始化

见 06。上线当天与备份、HTTPS 同一窗口执行，不要只换域名不换口令。
