# 06 账号权限初始化

## 原则

- **演示数据 ≠ 正式数据。** 当前公网库是样例品种/医院/追溯码，生产须独立库或清空后导入贵司主数据。  
- **长期 `admin/123456` 不能留在生产。**  
- 新口令只进密码柜，不进 Git、不进聊天、不进本文件。

## 当前演示库实况（2026-09-14）

| 登录名 | 显示名 | 角色 | available | 口令状态 |
|--------|--------|------|-----------|----------|
| admin | 超级管理员 | 超级管理员 | 1 | 弱口令 123456 |
| purchase | 采购员 | 采购员 | 1 | 同弱口令 |
| warehouse | 仓库管理员 | 仓库管理员 | 1 | 同弱口令 |

角色 5 个均已存在。缺的不是「没有岗位」，而是 **未按贵司人员启用、未轮换口令、超管仍日常登录**。

## 生产窗口（须在 HTTPS 开通同一天完成）

1. 甲方提供真实姓名、部门、岗位（采购 / 仓管 / 销售 / 财务；超管 1～2 名实名）。  
2. 在「人员信息」为每人建号，登录名不用 `admin`。  
3. 用系统「重置密码」或改密接口设置密码柜中的强口令（≥12 位，柜内各不相同）。  
4. 「角色管理」勾选对应角色；不要把超管角色批给业务岗。  
5. 用各岗位账号登录，确认菜单与 00 主链路匹配（采购能入库、仓管能库存/追溯、销售能出库/收货、财务看统计只读）。  
6. 将 `admin` 的 `available` 置 0，或改密后仅放应急柜、禁止日常使用。  
7. 演示库若升为生产：删除或停用样例医院/批号/追溯码，或切换空库再导入。

停用超管（在确认已有实名超管可登录之后）：

```sql
UPDATE sys_user SET available = 0, remark = '生产已停用弱口令超管' WHERE loginname = 'admin';
```

## 岗位与本期菜单（系统预置，待贵司对照）

| 角色 | 预期主操作 | 不作为本期验收 |
|------|------------|----------------|

GSP 质管/验收/养护若需独立登录角色，等 04 的对照表，不在本期宣称已按贵司落地。
